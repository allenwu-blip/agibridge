## What agibridge is

agibridge converts between two embodied-AI dataset formats in your browser:

- **AgiBot World** (OpenDriveLab — 1,001,552 trajectories / 2,976.4 hrs / 217 tasks across the 2026 release)
- **Hugging Face LeRobot v3** (consumed by Physical Intelligence's π0, Toyota Research's LBM, NVIDIA's Isaac GR00T)

You upload a tarball, pick a direction, and download the result. Every conversion runs an output verification report covering episode count, camera column names, action-vector shape, and timestamp monotonicity. The underlying converter is the open-source [`embodied-data`](https://pypi.org/project/embodied-data/) library (v0.3.1 GA on PyPI); the hosted layer adds auth, persistent storage, team workflows, and a pinned-version conversion pipeline.

## What agibridge is not

- Not an ML training platform. agibridge does not run inference on customer data.
- Not a dataset catalog. Your data stays in your per-organization storage prefix.
- Not a one-click "any-format → any-format" converter. The supported surface today is AgiBot World ↔ LeRobot v3. Open X-Embodiment, RLDS, LIBERO, and custom HDF5 schemas are on the roadmap, not the product.

## Why this exists

LeRobot v3 became the de-facto VLA training format in 2025, and the v2→v3 migration has been rougher than the official announcement suggests. Five open issues on `huggingface/lerobot` ([#2158](https://github.com/huggingface/lerobot/issues/2158), [#2128](https://github.com/huggingface/lerobot/issues/2128), [#2446](https://github.com/huggingface/lerobot/issues/2446), [#761](https://github.com/huggingface/lerobot/issues/761), [#846](https://github.com/huggingface/lerobot/issues/846)) document concrete breakage. Physical Intelligence's `openpi` script is pinned to LeRobot v2.1 ([openpi#443](https://github.com/Physical-Intelligence/openpi/issues/443)). AgiBot World's official repo is pinned to LeRobot v2 commit `2b71789`. If you train VLAs on multiple upstream datasets, a non-trivial fraction of your week goes to downgrading dependencies and patching deprecated scripts.

agibridge pins the conversion pipeline to a known-good `embodied-data` v0.3.1 + LeRobot v3 version. A conversion you run today produces the same output as one you ran last month, no version drift between users, no "works on my Python 3.11 but not your 3.12".

## Self-hosting is supported

The underlying converter is Apache-2.0 open source. If you would rather run conversion locally:

```bash
pip install embodied-data==0.3.1
embodied-data convert --source agibot_world --target lerobot_v3 ./input.tar.gz ./output/
```

The hosted backend pins the same library version published on PyPI. Self-hosted output is byte-identical to hosted output for the same pinned version. See the [Pricing concepts page](/concepts/pricing) for the honest framing on self-host vs hosted.
